# proxy-release 仕様

[仕様索引へ戻る](../../SPEC.md)

## 目的

`proxy-release` は、MUGENキャラクターやステージなどの代理公開所向けフロントエンドです。投稿されたzipを保管し、タグと作者で整理して一覧表示します。データモデルと管理機能は materials-library をベースにします。

## 現在の挙動

- materials-library と同じ素材投稿APIと runtime テーブルを利用します。
- 代理公開の初期設定では、投稿ファイル形式を `zip` に限定します。
- MUGENキャラクターzipを選択すると、ブラウザ内で `.air` と `.sff` を読み取り、待機モーションGIFの自動生成を試みます。
- Character DEFの `pal1`〜`pal12` が参照する既存ACTを番号順に表示し、`pal1` を初期選択します。選択変更時はWebMUGENのSFF v1実装から同期したパレット処理でGIFを再生成します。
- 説明用画像を手動選択した場合は、自動生成GIFより手動画像を優先します。
- HOME、一覧、投稿、削除、編集、取説、ログイン、管理画面は materials-library 相当の操作体系です。
- 上部メニューの `試遊` は `ログイン` の右側に表示します。
- 試遊リンク先は管理画面の設定から変更できます。URL未設定時はクリックできない無効表示にします。
- 公開カードの主操作は、アクセント色で塗りつぶした白太字の `Download` ボタンとして表示します。
- 管理画面の設定から、保存済み試遊URLを削除せず、各カードの試遊ボタンを一括非表示にできます。既定は表示です。

## 代理公開向け設定

- legacy 代理公開データの取り込み後は、タグとして `MUGENキャラクター` と `MUGENステージ` などを使います。
- 利用規約は、動画使用、改変、AI作成、素材流用、改変物配布、2次配布など、MUGEN代理公開に必要な項目を設定できます。
- 管理画面のデザイン機能で legacy 風の緑基調へ変更できます。ただしデフォルトカラーは materials-library と同系統のグレー基調です。

## 見た目

- 一覧カードは materials-library の構成をベースにしつつ、カード外枠を抑え、説明画像がカードからはみ出して見える表示を許容します。
- メニューやフォームは他の ThreadForge フロントエンドと同じ操作感に寄せます。

## 注意

- Proxy Releaseは単独配備可能な状態を保ちます。DEF・文字コード・ACTの純粋処理だけを記録済みWebMUGEN commitから同期し、SFF v1では同じ外部ACT・逆順インデックス処理を使います。WebMUGEN側のSFF v2処理には変更を加えません。
- AIR/SFF の解析に失敗しても、手動で説明用画像を添付できます。
- リリースZipには runtime DB とアップロード済みファイルは含めません。

## 管理画面とWebMUGEN連携

- 公開種別（`normal` / `test`）と可視性（`public` / `unlisted`）は独立して保持します。現在は通常公開を `normal + public`、7日間のテスト公開を `test + unlisted` とし、テスト公開はWebMUGEN Catalogへ登録しつつ通常のコンテンツ選択画面には表示せず、専用試遊URLからだけ選択できます。
- テスト公開の初回WebMUGEN登録時に128ビットの暗号学的乱数を一度だけ生成して保存します。試遊URLのCatalog IDには連番の公開IDではなくこのアクセスキーを使用し、再登録・正式公開への昇格・Catalog再構築・削除でも同じキーを維持します。

- `データ編集` タブでは、既存公開データをID・名称・作者名・ZIPファイル名で検索し、通常の公開項目と保存先などの管理用情報を確認・編集できます。
- 管理者はHTTP/HTTPSの試遊URLを手動保存できるほか、各データをWebMUGENへ個別登録・再登録できます。
- 個別登録と再登録は毎回同じpublicationIdを送り、`proxy-release-<ID>` を安定キーとしてCatalogをupsertします。
- `保守` タブでは、公開済みかつ試遊URL未設定のデータだけを一括登録できます。1件失敗しても残りの処理を継続し、対象・成功・失敗件数と失敗理由を表示します。
- 公開APIと公開カードには、保存済みの試遊URLだけを出します。Character ID、実保存先、連携失敗理由は管理者専用です。
