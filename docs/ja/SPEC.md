# ThreadForge 現在仕様

[English specification](../SPEC.md)

ThreadForge は、投稿、画像、返信、モデレーション、コミュニティアーカイブを扱う軽量でカスタマイズ可能なスレッド掲示板エンジンです。

ThreadForge は、作品投稿、メディア投稿、制作ログ、小規模コミュニティ、アーカイブ用途に適用できる新しいセルフホスト型掲示板エンジンです。

## ランタイム構成

- `client/`: React 18 + TypeScript + Vite の SPA
- `server/api.php`: PHP API エントリポイント
- `server/db.php`: SQLite 接続、スキーマ初期化、ストレージ補助
- `server/database.sqlite`: 実行時 SQLite DB。Git 管理外
- `server/storage/data/`: アップロード画像。`.gitkeep` 以外は Git 管理外
- `docs/`: プロジェクトドキュメント

## ルート

- `/`: スレッド一覧
- `/thread/:id`: スレッド詳細、返信、返信フォーム
- `/thread/:id?mode=eejanaika`: 固定文返信フォーム
- `/post`: 新規親投稿フォーム
- `/search`: 検索ページ
- `/delete`: 削除モード
- `/edit`: 編集モード
- `/edit/:id`: 指定投稿または返信の編集
- `/ranking`: 順位ページ
- `/login`: ログイン、ユーザー設定、個人アナリティクス
- `/user/:id`: 指定ユーザーの作品一覧
- `/analytics`: ログイン中ユーザー向けの作品統計
- `/admin`: 管理画面
- `/manual`: 組み込みマニュアルページ

## コア機能

- 親投稿の作成、返信の作成、投稿/返信の編集、削除
- 親投稿のみ画像アップロード可能。返信では画像アップロード不可
- 管理画面で許可された画像形式だけを受け付ける。初期設定は GIF、PNG、JPEG、JPG、BMP
- 投稿前と編集時の画像プレビュー
- 親投稿のみSNS転記プレビューとSNS転記
- X、Bluesky、Mastodon、Misskey 連携はデフォルトOFF
- X連携は未デバッグであり、現時点では動作を保証しない
- 親投稿のSNS転記先URL/ID保存とリアクションキャッシュ表示
- SNS転記OFFモード
- 特殊投稿モード。表示名は管理画面で変更可能
- 表示番号は親投稿だけに割り当て、返信はスレッド内の子番号を使う
- クラシックなトップナビゲーション
- トップページにスレッドごとの返信を最大10件表示
- コメントまたは簡単リアクション送信後、スレッド詳細ページに留まる
- 3種類の簡単リアクション。文言と文字色は管理画面で変更可能
- 投稿/返信の編集回数 `rev01` 表示と、編集日時のツールチップ
- 投稿パスワードによる編集と削除
- 内部データを残すソフトデリートと、管理画面からの削除済み投稿の復元/消去
- 投稿パスワード不要の管理者一括削除。画面選択と範囲指定に対応
- 投稿、返信、編集履歴、ユーザー、作品登録、アクセス履歴、画像、設定を含む管理画面フルバックアップZIPのエクスポート/インポート
- 掲示板設定JSONと掲示板デザインJSONのインポート/エクスポート
- ローカル運用バッチまたはPHPコマンドによるローカルアーカイブ `LOG_*.cgi` の非破壊インポート
- `tools/build_release.ps1` による配布用Zip作成
- `config.cgi` と `skincfg.cgi` 相当の管理設定保存
- 管理画面からの HOME リンク、掲示板/取説タイトル、取説本文、SNS設定、アップロード制限、配色設定
- キーワードと対象範囲を指定できる検索。検索結果は一覧の該当投稿位置へリンク
- 順位ページ。コメント数、閲覧数、リアクション数などを同順位対応で表示
- アクセスカウンタと投稿作品アナリティクス
- ユーザー登録、ログイン、プロフィール、アイコン、個人アナリティクス、自分の作品として登録
- 作者アイコンの拡大表示とユーザー別作品一覧
- RSSフィード

## 管理機能

管理画面はDBに保存された管理者パスワードを使います。初回はブラウザの管理画面で管理者パスワードを設定します。復旧や自動セットアップ補助用に `THREADFORGE_ADMIN_PASSWORD` も利用できます。

実装済み:

- 一括削除: 通常投稿と返信を複数選択、または親投稿番号の範囲を指定し、個別投稿パスワードなしで削除
- 復元/消去: `deleted_at` が設定された投稿/返信の復元、データ消去、番号ごとの完全削除
- 保守: 管理者パスワード変更、SNSリアクション更新、投稿番号の投稿日順採番しなおし、フルバックアップZIPのエクスポート/インポート
- 保守内ユーザー登録情報: 登録済みユーザーの情報編集、登録情報の消去、ユーザー番号ごとの完全削除
- アナリティクス: 投稿数、コメント数、アクセス数、閲覧数、簡単リアクション数、SNSリアクション数を日/月/年の合計、平均、累積で表示
- 掲示板設定: HOMEリンク、取説本文、特殊投稿、親サイトSSO、SNS連携、cron情報、一覧の並び順、画像アップロード制限、許可画像形式を編集
- 掲示板デザイン: 簡単リアクションの文言/文字色/ボタン背景色、背景、パネル、投稿枠、入力欄、ボタン、注意文、状態色などを編集し、すべての色設定をサンプル画面で即時確認
- 掲示板設定JSONと掲示板デザインJSONのエクスポート/インポート
- SNSリアクション自動更新用のローカルCronパスとAPIキー付きURLの表示
- DBがない初期状態では、特殊投稿OFF、一覧の並び順はNo順、SNS投稿ハッシュタグ `#art`、SNS連携すべてOFF、SNS認証情報空欄
- 一覧の並び順はNo順または投稿日順（新しい順）を選択可能
- 一覧画面では年/月を複数指定して投稿を絞り込めます。年は1行ずつ表示し、月は1月から12月まで同じ横位置に揃えて表示します。投稿件数は画面上に常時表示せず、年または月にカーソルを合わせたポップアップで表示します。年だけの指定はその年全体、月指定はその月だけを対象にし、指定期間の総投稿数を表示します。期間指定中は投稿日が新しい順に表示します。
- 削除、編集、管理画面の一括削除、復元/消去など、投稿を一覧で確認する画面にも同じ年月フィルタを表示します。管理画面の一括削除と復元/消去は、公開一覧の表示件数設定に左右されず、管理対象の投稿を全件取得します。
- 最大アップロードサイズは管理画面ではKB表示、内部設定ではbyte保存

メモ:

- 保存済み `config` と `skin` 設定は管理APIで永続化します。
- 公開UIは公開設定APIから安全な設定だけを読みます。
- Web管理画面ではローカルアーカイブログを取り込みません。ローカルアーカイブの非破壊インポートは運用バッチまたはPHPコマンドで実行します。

## 親サイトSSO

親サイトでログイン済みのユーザーを、配下のThreadForgeへ引き継ぐための簡易SSOを用意しています。

- 管理画面の掲示板設定で「SSOログイン」をONにし、「SSO共有秘密鍵」を設定します。
- 親サイトはJSONペイロードをBase64URL化し、その文字列を共有秘密鍵でHMAC-SHA256署名します。
- トークン形式は `base64url(payload).base64url(hmac_sha256(base64url(payload), secret))` です。
- ペイロードには `login_id` または `sub`、`exp` を必須で入れます。任意で `display_name`、`post_password`、`home_url`、`iat` を渡せます。
- 親サイトは `index.html#/login?sso=<token>` へ遷移させます。ThreadForgeは署名と有効期限を検証し、既存ユーザーならログイン、未登録ならユーザーを自動作成します。
- SSOトークンはURLに載るため、短い有効期限にしてください。ログイン完了後、ThreadForgeはURLから `sso` パラメータを取り除きます。
- `THREADFORGE_SSO_SECRET` 環境変数も秘密鍵として利用できますが、SSO機能自体は管理画面でONにする必要があります。

## データモデル

主テーブルは SQLite の `posts` です。

主なカラム:

- `id`
- `thread_id`
- `parent_id`
- `name`
- `url`
- `title`
- `message`
- `image_path`
- `password_hash`
- `created_at`
- `deleted_at`
- `gdgd`
- `tweet_off`
- `tweet_text`
- `tweet_url`
- X/Tweet のいいね、リポスト、閲覧数カラム
- Bluesky の URI/CID/URL と Like/Repost/Quote 数
- Mastodon の ID/URL と Boost/Fav 数
- Misskey の ID/URL とリアクション数

`settings` テーブルは、管理画面で扱う設定セクションをJSONとして保存します。`security` セクションには `adminPasswordHash` と `cronApiKey` を含みます。

ログイン機能は `users`、`user_sessions`、`user_post_claims` を使います。`user_post_claims` は投稿本体の所有者を書き換えず、ユーザー側に「自分の作品」として紐づけるためのテーブルです。

公開UIは `?action=publicSettings` から安全な設定だけを読みます。

## SNS転記ルール

- SNS転記は、新規投稿フォームの `SNS転記OFF` スイッチで制御します。
- 管理画面では X、Bluesky、Mastodon、Misskey の設定を分けます。
- 各SNSがOFFの間、そのSNSの認証情報欄は無効化されます。
- 新規の親投稿だけが、有効なSNSへ転記されます。
- 親投稿の編集は掲示板内だけに反映し、SNS側の編集・再投稿は行いません。
- 投稿削除時は、対応するSNS投稿の削除も試みます。
- 返信はSNS転記しません。返信フォームにはSNSコントロールを表示しません。
- 画像付き親投稿では、X、Bluesky、Mastodon、Misskey へ画像も送信します。
- 有効なSNSごとに読み取り専用のプレビューを表示します。
- `_TWEND_` 以降の本文はSNS転記対象外です。
- SNS本文には `最新はこちら` と `/#post-000001` のような掲示板一覧リンクを含めます。一覧ページでは該当投稿位置へスクロールします。
- 文字数上限を超える場合、ThreadForge は `..` で省略して送信します。
- 既定上限は X 280、Bluesky 300、Mastodon 500、Misskey 3000 です。
- X は重み付き文字数、それ以外は通常の文字数でプレビューします。
- キャッシュ済みリアクション数は同色のシンプルな指標として表示します。
- リアクション更新は管理画面、ローカル `server/cron.php`、`server/cron.php?api_key=...`、または `?action=cronRefreshSocialReactions&api_key=...` から実行できます。
- `server/cron.php` はブラウザからのキーなし実行を拒否します。外部URL型CronではAPIキー付きURLとして呼び出し、実行ログに `cron web social reaction ...` を残します。
- 自動リアクション更新は、SNS投稿IDを持つ未削除親投稿すべてを対象にします。

## コメントと固定文返信フォーム

- コメントフォームは名前、URL/HOME、本文、パスワードを使います。
- コメントでは名前、本文、パスワードが必須です。
- UI上の案内では、パスワードは8文字以内の半角英数字です。
- 固定文返信フォームは名前を入力し、固定返信文を1つ選びます。
- インラインコメントと固定文返信フォームには閉じるボタンがあり、下書きを閉じるときは確認します。
- インラインフォームを開いている間、スレッド操作ボタンは隠します。

## ストレージルール

- アップロード画像は `server/storage/data/` に保存します。
- 許可画像形式は管理画面から選択できます。初期設定は GIF、PNG、JPEG、JPG、BMP です。
- 実行時DBとアップロード画像は Git 管理外です。
- フルバックアップは管理画面のエクスポート機能からZIP形式で行います。現在の形式はSQLite DB本体と画像をZIPに収める方式です。大量投稿でもJSONへ全展開しないため、メモリ使用量を抑えます。ログインセッションは含めず、復元後は再ログインします。過去バージョンのJSON形式バックアップもインポート互換として読み込めます。
- 投稿画像を差し替える場合、古い画像はすぐ削除せず履歴名へ退避します。
- ローカルアーカイブログインポートは画像をストレージへコピーし、名前・本文・時刻が一致する既存投稿/返信をスキップします。Web管理画面ではなくローカルで実行します。
- ローカルアーカイブログインポートは `tools/import_local_archive.bat` から実行します。例: `tools\import_local_archive.bat legacy\data`
- 配布用Zipは `tools/build_release.ps1` で作成します。Zip内は `index.html`、`assets/`、`api.php`、`db.php`、`cron.php`、`storage/data/` を公開ディレクトリへそのまま置ける構成です。`database.sqlite`、`storage/data/` の実画像、運用スクリプトは含めません。
- クリーン初期化はサーバー停止後、`server/database.sqlite` と `server/storage/data/` 配下のファイルを削除して行います。詳細は `docs/ja/DB.md` を参照してください。

## 削除ルール

通常の削除はソフトデリートです。

- 通常UIから投稿が見えなくなります。
- DBには `deleted_at` 付きでデータが残ります。
- 管理画面の「復元/消去」から復元できます。
- 親スレッドを削除すると、その返信もソフトデリートします。
- 「復元/消去」では削除済み投稿を2段階で消去できます。
- 1段階目の「消去」は、本文、画像、返信、SNS情報、編集履歴、作品紐づけなどの実データを消去し、親投稿の表示番号は残します。
- 2段階目の「番号ごと消去」は、投稿行そのものを削除します。親投稿を削除した場合、以後の親投稿の表示番号は前詰めされます。
- 先頭の公開投稿より前に番号だけが残っている場合は、復元/消去に「番号だけ残っている削除データ」として表示し、番号ごと消去できます。
- 一括削除と復元/消去では、`1-10, 15` のような親投稿番号の範囲指定を使えます。

## ユーザー登録情報の管理

管理画面の保守タブから登録済みユーザーを管理できます。

- 保守から専用画面へ移動する前に確認メッセージを表示し、承認後にユーザー一覧と編集欄を表示します。
- ユーザー一覧では、No、名前、ログインID、作成日時、最終ログイン日時を確認できます。編集欄では、名前、URL/HOME、投稿パスワード、ログインパスワード再設定を編集できます。現在のログインパスワードは安全のため表示しません。
- 編集欄ではID、表示名、投稿パスワード、URL/HOME、新しいログインパスワードと確認欄を扱えます。
- ログインパスワードはハッシュで保存するため現在値を表示しません。管理者は新しい値を二度入力して再設定でき、入力内容は表示切替で確認できます。
- ユーザー情報の編集では、ID重複と表示名30文字制限を確認します。
- ユーザー削除は2段階です。
- 1段階目の「情報消去」は、ログインIDを退避名へ変更し、名前、投稿パスワード、URL/HOME、アイコン、ログインセッションを消去します。ユーザー番号は残します。
- 2段階目の「番号ごと消去」は、ユーザー行を削除し、残ったユーザー番号を前詰めします。対象ユーザーが直接投稿した投稿の `user_id` は外します。

## 公開名称

公開プロジェクト名は `ThreadForge` です。

公開UI、パッケージメタデータ、リポジトリメタデータ、公開ドキュメントでは `ThreadForge` を新規ソフトとして扱います。

## バージョン管理

プロジェクトはセマンティックバージョニングで管理します。

現在のバージョン: `0.9.0`

バージョン参照は次のファイルで同時に更新します。

- `VERSION`
- `CHANGELOG.md`
- `client/package.json`
- `client/src/version.ts`

PHP API は `?action=version` で現在バージョンを返します。
